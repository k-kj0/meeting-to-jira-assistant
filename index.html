Intent classification.

Most tools create a ticket for every sentence with "should." This one reads the room.

⚡

Commitment signal detection

Future-tense verbs + a named person = action item. Passive voice suggestions — "someone could look into X" — are filtered before any ticket is ever created.

👤

Assignee extraction

Named entity recognition pulls owners from natural language. "John said he'd handle the deploy" correctly assigns to John — no triage required.

📅

Deadline normalization

"By Thursday", "EOD", "next sprint" are all parsed and normalized to ISO 8601 dates before hitting the Jira API.

🔗

Typed JSON output

The model returns a strict schema — no freeform text, no regex parsing downstream. Every field is typed and validated before the Jira write.

extractor.py 
# One API call — entire transcript, strict JSON schema back
def extract_tickets(transcript: str) -> list[ActionItem]:
    response = client.messages.create(
        model="claude-sonnet-4-20250514",
        system=SYSTEM_PROMPT,    # few-shot commitment examples
        messages=[{"role": "user", "content": transcript}]
    )
    # Typed schema — zero regex parsing needed downstream
    raw = json.loads(response.content[0].text)
    return [ActionItem(**item) for item in raw["action_items"]]
 
# System prompt key instruction:
# "Only extract COMMITTED tasks with a named owner.
#  If a sentence is a suggestion or vague, omit it entirely."
FAQ

Questions,
answered.

Does it actually write to Jira?+
Yes. The backend uses the Atlassian REST API v3 with OAuth 2.0. You authenticate once, the token is stored locally, and tickets go directly to whichever project you configure. The interactive section above runs locally and returns parsed output — no Jira write happens without your credentials set up.
How does noise filtering actually work?+
The system prompt includes few-shot examples teaching the model what "committed" means: a named person, a future-tense verb, and a clear scope. Vague suggestions without a named owner are explicitly excluded in the schema definition.
Is transcript content stored anywhere?+
No. Transcripts are sent to the API and immediately discarded after the response. The backend is stateless — nothing is persisted between requests.
What Jira plan is required?+
Jira Cloud free tier and above. You need an Atlassian API token — setup takes under two minutes and is fully documented in the GitHub README.
Does it handle large transcripts with multiple speakers?+
Yes. A 90-minute all-hands typically produces 12–20 tickets, each correctly attributed. The model handles speaker labels, crosstalk, and messy punctuation without preprocessing.
